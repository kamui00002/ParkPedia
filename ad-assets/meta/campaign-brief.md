**作成日**: 2026-05-11
**対象アプリ**: ParkPedia (iOS / v1.1.3 公開後配信開始)
**プラットフォーム**: Meta (Facebook + Instagram, Advantage+ Placements)
**キャンペーン目的**: アプリインストール獲得 (App Promotion / App Installs)
**配信開始予定**: 2026-05-15 頃
**テスト期間**: 30 日間
**App Store**: https://apps.apple.com/app/id6755152821

## 1. キャンペーン概要

### 1.1 基本スペック

| 項目 | 値 |
|---|---|
| 目的 | アプリインストール獲得 (学習フェーズ) |
| 月間予算 | ¥10,000 |
| 日次予算 | ¥333 |
| 対象国 | 日本 (JP) |
| 対象言語 | 日本語 (ja) |
| 配信フォーマット | フィード正方形 (1080x1080) / フィード縦長 (1080x1350) / ストーリー縦長 (1080x1920) |
| プレースメント | Advantage+ Placements (自動最適化) |
| 入札戦略 | Highest Volume (デフォルト) |
| キャンペーン構造 | 1 キャンペーン / 1 広告セット / 3-9 クリエイティブ |
| 計測 | SKAdNetwork (主) + Meta Aggregated Event Measurement (副) |

### 1.2 KPI 目標

| 指標 | 目標 | 撤退基準 |
|---|---|---|
| 月間インストール数 (Primary) | 20-33 件 | < 10 件で 30 日経過 |
| CPI (Cost Per Install) | ¥300-800 (中央 ¥500) | > ¥1,200 が 7 日連続 |
| Day7 リテンション (副次) | > 15% | データ取得できる場合のみ参考 |
| SKAN ポストバック数 | インストールの 80%+ | < 50% が継続 |

### 1.3 現実的な期待値の前提

- **過去実績**: AdMob 収益化側で週¥6 / 週インプレッション 26 件 / eCPM ¥231 という極めて小規模なトラクション。**Meta UA は「収益の前に学習」が目的**。
- **ATT 拒否率**: 日本市場では一般的に 70-80% 想定。**SKAN 中心の計測になり、Day7/Day14 のユーザー単位リテンションは限定的にしか見えない**。
- **学習フェーズ突破は困難**: Meta の学習フェーズ突破基準は 50 conversion/7日。月¥10K では到達しない前提で、**「クリエイティブ A/B より、3 訴求軸の自然比較で何が刺さるかを観察する」設計**にする。

## 2. ペルソナ深掘り

### 2.1 Primary: 子連れママ・パパ (30-45歳)

#### 1日の動線
- **平日朝**: 子供の保育園/学校送り → SNS チラ見 (通勤電車・洗濯中)
- **平日昼**: ランチ後の休憩で Instagram のフィード/ストーリーを 5-10 分閲覧
- **平日夜 (特に金曜)**: 子供が寝た後、夫婦で「明日どこ行く?」会議。Google マップや「いこーよ」を検索。**ここが最大のトリガー**。
- **土日朝**: 出発前の最終確認。「駐車場ある?」「トイレある?」を慌てて検索。
- **雨上がりの晴れ間**: 「外で遊ばせたい」と急に思い立ち、近所のスポットを探す。

#### 心理状態
- **罪悪感ベース**: 「週末またショッピングモールに連れて行くだけになる…」「自然と触れ合わせたい」
- **失敗回避**: 「せっかく連れて行ったのに遊具が小さすぎた」「駐車場満車で帰る」が一番怖い
- **比較疲労**: Google マップの星評価はあてにならない。ステマっぽいブログも信用できない。
- **時間がない**: 計画立てに 10 分以上かけたくない

#### トリガーモーメント (広告が刺さるタイミング)
1. **金曜夜 20:00-23:00**: 「明日どこ連れて行く」検索ピーク
2. **土曜朝 7:00-9:00**: 出発前の最終確認
3. **日曜午後 14:00-17:00**: 「来週末こそは」の予習タイミング

### 2.2 Secondary: 犬の散歩・ウォーキング層 (40-65歳)

#### 1日の動線
- **早朝/夕方の犬散歩**: 同じコースに飽きている。Instagram は使うが Facebook の方がアクティブ。
- **週末**: 少し遠出して「犬OK の公園」を探したいが、検索が手間。
- **退職前後 (60代)**: 健康のためのウォーキングコース探し。歩数・距離より「気持ち良く歩ける場所」が重要。

#### 心理状態
- **マンネリ感**: 「いつもの公園、犬も飽きてるかも」
- **情報源不足**: 犬OK 公園は Google マップに明記されていない。フェンスや水飲み場の有無も不明。
- **コミュニティ欲求**: 同じ散歩仲間に「あそこ良かったよ」とシェアしたい

#### トリガーモーメント
1. **平日早朝 5:30-7:30**: 散歩前のスマホチェック
2. **休日午前**: 「今日はどこ行こうか」の発想転換
3. **季節の変わり目**: 桜・紅葉シーズンに新スポット欲が高まる

## 4. クリエイティブ仕様

### 4.1 Meta 推奨フォーマット

| フォーマット | サイズ | 配置 | 用途 |
|---|---|---|---|
| フィード正方形 | 1080 x 1080 | Facebook/Instagram フィード | 汎用、最も配信量が多い |
| フィード縦長 | 1080 x 1350 | Facebook/Instagram フィード | モバイル占有率高、CTR 期待 |
| ストーリー縦長 | 1080 x 1920 | Stories/Reels | 没入感、若年層・忙しい親に強い |

### 4.2 共通ガイドライン

- **テキスト率**: 画像内テキストは全体面積の **20% 以下** (Meta の旧20%ルールは公式撤廃済みだが、CTR 観点で依然有効)
- **ロゴ**: 必須ではないが、片隅に小さく ParkPedia ロゴ (#4CAF50 アイコン) を配置可
- **色調**: Park Green (#4CAF50) を差し色に。背景の自然光・緑とのトーン一致
- **被写体**: 実在感のある自然な家族・親子・公園シーン。**ストックフォトでも「合成感のないもの」を厳選**
- **顔出し**: 子供の顔は横顔・後ろ姿・遠景でぼかし気味に。プライバシー配慮
- **音声/動画**: 初期テストは静止画のみ。動画は次フェーズで検討

### 4.3 訴求軸 × フォーマット マトリクス (9 案)

| | A. 家族 | B. 発見 | C. レビュー |
|---|---|---|---|
| **1080x1080 フィード正方形** | A-1: 芝生で遊ぶ親子の俯瞰 | B-1: 桜並木の小径 | C-1: スマホ+公園合成 |
| **1080x1350 フィード縦長** | A-2: ピクニックシート + 子の手 | B-2: 季節の公園ベンチ | C-2: チェックリスト風 |
| **1080x1920 ストーリー縦長** | A-3: 動きのある遊具シーン | B-3: 夕暮れの公園 | C-3: 「失敗しない週末」コピー |

初期投入は **9 案フル**ではなく、**訴求軸ごとに 1 フォーマットずつ計 3 案** (A-1, B-1, C-2 を推奨) でスタート。月¥10K では Meta のアルゴリズムが捌けるクリエイティブ数に上限があるため、**「広げすぎない」のが鉄則**。

## 5. 配信戦略

### 5.1 オーディエンス: Advantage+ Audience に全振り

#### 根拠
- **月¥10K は手動セグメント分割に耐えない予算**。3 セグメントに分けたら 1 セグメント¥3K/月で、学習データが集まらない。
- Meta の機械学習は **App Install 目的なら Advantage+ Audience が手動より平均 -28% CPI** (Meta 公式 2024 ベンチマーク)。
- **興味カテゴリの「子育て」「公園」「ペット」を Audience Suggestion として軽く設定**するが、Meta に絞り込みを強制しない。

#### 設定
- 年齢: 28-65 歳 (Primary 30-45 + Secondary 40-65 を緩めにカバー)
- 性別: 全て (女性偏重を Meta に任せる)
- 地域: 日本全国
- 興味 (Suggestion のみ): 子育て / 公園 / アウトドア / ペット (任意)
- カスタムオーディエンス: なし (まだトラフィックなし)
- 類似オーディエンス: なし (シードがない)

### 5.2 プレースメント: Advantage+ Placements

- **全プレースメント自動**
- Reels、Stories、Feed、Marketplace、Audience Network まで含める
- **Audience Network 除外はしない** — 低 CPM で配信量稼ぐため
- 配信開始 14 日後にプレースメント別 CPI を見て、明らかに悪いものだけ手動除外検討

### 5.3 入札戦略

- **Highest Volume (旧 Lowest Cost)** で開始
- Cost Cap は使わない (月¥10K では学習が止まる)
- 入札上限は設定しない

### 5.4 A/B テストはしない、訴求軸間の自然比較で観察

#### A/B テスト不可な理由
- Meta の公式 A/B テスト機能は **各セルに最低 50 conversion/週 を推奨**。
- 月¥10K / 想定 CPI ¥500 → 月 20 install → **A/B 2 セルに分けたら統計的に何も言えない**。

#### 代替アプローチ: クリエイティブ間の自然比較
- **1 広告セット内に 3 クリエイティブ (A-1, B-1, C-2) を投入**
- Meta が自動で配信比率を最適化 (Dynamic Creative Optimization に似た挙動)
- 14 日経過時点で **「Meta が偏らせた配信比率」自体が示唆**になる
  - 例: 「A (家族) に 70% 配信されている」→ Meta は A が最もインストールに繋がると判断した
- **統計的有意性は問わない**。「学習」が目的なので、観察ベースで次月の方向性を決める

### 5.5 配信スケジュール

- **24 時間配信** (時間帯絞りは予算が小さすぎて意味がない)
- ただし配信開始から 48 時間は手動で監視
- **金曜夜・土曜朝にインプレッションが集中するか** をオーガニックに確認

## 6. KPI と撤退基準

### 6.1 判断タイムライン

| 経過 | 確認内容 | 判断基準 |
|---|---|---|
| **48 時間** | 配信が開始されたか、極端な異常はないか | CPI > ¥3,000 だったらクリエイティブ即差し替え |
| **7 日 (¥2,331 消化)** | 初期インストール数、SKAN ポストバック有無 | install 2 件未満 → クリエイティブ 1 枚追加投入 |
| **14 日 (¥4,662 消化)** | クリエイティブ別配信比率、CPI トレンド | CPI > ¥1,200 が続く → 訴求軸の見直し |
| **30 日 (¥10,000 消化)** | 月間総括、継続/撤退判断 | install 10 件未満 → 撤退または訴求軸全面見直し |

### 6.2 継続条件

- 月間 install **20 件以上** 達成
- CPI **¥800 以下**
- SKAN ポストバック **8 件以上** (オーガニックと区別可能なレベル)

### 6.3 撤退条件

- 14 日連続で CPI > ¥1,500
- 30 日経過で install 10 件未満
- App Store のクラッシュレートが Meta 流入ユーザーで急増した場合

### 6.4 撤退ではなく見直しのケース

- install は出ているが Day1 リテンション 0% に近い → クリエイティブと LP (App Store ページ) のミスマッチ。**クリエイティブよりまず App Store スクリーンショット見直し**
- 特定のクリエイティブだけ CPI が高い → そのクリエイティブだけ停止、残りで継続

## 7. NG 事項

### 7.1 Apple / Meta ガイドライン違反になりやすいパターン

- **「ダウンロード必須!」「絶対!」などの煽り表現** → Meta 広告ポリシー違反、CTR にも逆効果
- **アプリ機能を誇張する表現** ("AI が公園を推薦!" → 実際はユーザー投稿型) → App Store Review でリジェクト要因
- **位置情報の常時取得を匂わせる訴求** → ATT 配慮、ParkPedia は位置情報を常時取得しない
- **子供の顔がはっきり写った素材** → 肖像権、Meta ポリシー、家族層の不快感
- **「無料!」を強調しすぎる** → Meta は無料を訴求すること自体は OK だが、煽ると CTR は上がるが install 後の継続率が悪化する
- **「日本一」「No.1」などの最上級表現** → 景表法、根拠なしは NG

### 7.2 Park Green トーンを壊す表現

- **極彩色の派手なフィルター** → 自然光・ナチュラル感を損なう
- **絵文字の多用** (見出しに 2 個以上) → ブランドの voice_and_tone.vocabulary に反する
- **「!!!」の連打** → 親しみやすさを失う
- **海外の公園写真** → 「ご近所」感が消える、ローカル訴求の核を破壊
- **スタジオライティングの合成感のある画像** → ドキュメンタリー感のあるリアリティが失われる
- **テキストだらけのバナー風デザイン** → CTR 低下、imagery_avoid に明記

### 7.3 NG コピー例

- ❌ 「🌟絶対行くべき!最強の公園アプリ💯今すぐDL!!!」 (brand-profile の example_bad そのもの)
- ❌ 「全国 No.1 の公園アプリ!」 (根拠不明、景表法リスク)
- ❌ 「AI があなたにピッタリの公園を提案!」 (機能誇張)
- ❌ 「これを知らないと損!」 (煽り)

### 7.4 OK コピー例

- ✅ 「今日のお散歩、どの公園にする?ご近所の隠れた名所、見つかるかも。」
- ✅ 「週末『どこ行く?』に、もう迷わない。」
- ✅ 「歩いて 10 分のところに、こんな公園があったなんて。」

## 8. 次フェーズへの引き継ぎ

### 8.1 copy-writer へ渡す要点

- **訴求軸 3 本** (A: 家族 / B: 発見 / C: レビュー) それぞれにヘッドライン 2-3 案、プライマリーテキスト 1-2 案、CTA 候補 2 個ずつ
- **トーン**: 敬体・親しみやすい・煽らない (brand-profile.voice_and_tone 厳守)
- **文字数制限**:
  - Primary Text: 125 文字以内推奨 (Meta は 280 文字まで OK だがモバイルで切れる)
  - Headline: 27 文字以内
  - Description: 27 文字以内 (フィード広告のみ表示)
- **絵文字**: 見出し 1 個まで、本文は基本なし
- **ローカル感を出す語彙**: 「ご近所」「お散歩」「週末」「ちょっと出かける」など
- **避ける語彙**: 「絶対」「必見」「最強」「No.1」「神」「ヤバい」

### 8.2 visual-designer へ渡す要点

- **3 案を優先制作**: A-1 (1080x1080 家族・芝生)、B-1 (1080x1080 桜並木の小径)、C-2 (1080x1350 チェックリスト風)
- **ビジュアル素材**:
  - 自然光・ドキュメンタリー風・日本の公園
  - 子供の顔はぼかし or 後ろ姿
  - Park Green (#4CAF50) を差し色に
  - ロゴは右下に小さく (5% 以内のサイズ)
- **テキスト率 20% 以下厳守** — Meta の Text Overlay Tool で事前チェック
- **既存資産**:
  - ロゴ: `/Users/yoshidometoru/Documents/GitHub/ParkPedia/assets/icon.png`
  - 旧試作: `/Users/yoshidometoru/Documents/GitHub/ParkPedia/ad-assets/meta/feed-1080x1080-v1.png` (v1.1.2 時代、参考程度に)
  - App Store スクリーンショット: ストアページから取得
- **避けるべき表現**: imagery_avoid のリスト (スタジオ照明、クリップアート、海外公園、派手フィルター、テキストだらけ)
- **出力**: PNG (透過不要)、sRGB、1MB 以下推奨

### 8.3 配信オペレーターへ渡す要点

- **キャンペーン構造**: 1 キャンペーン / 1 広告セット / 3 クリエイティブ (A-1, B-1, C-2)
- **目的**: App Installs (App Promotion)
- **予算**: 日次予算 ¥333 / キャンペーン (広告セットではなく)
- **入札**: Highest Volume
- **オーディエンス**: Advantage+ Audience、興味 Suggestion = 子育て/公園/アウトドア/ペット
- **配置**: Advantage+ Placements (全自動)
- **計測**:
  - SKAN: Meta SDK の SKAN Conversion Schema 設定要 (secrets 配置後)
  - Meta Aggregated Event Measurement: install イベント優先度 1
- **トラッキング**: ATT ダイアログ表示後、許可ユーザーのみ詳細計測。拒否ユーザーは SKAN のみ
